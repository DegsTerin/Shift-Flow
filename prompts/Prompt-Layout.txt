# Revisão Completa de UI/UX, Design System e Layout da Aplicação

Realize uma revisão completa de toda a aplicação, abrangendo todas as páginas, módulos, componentes, layouts, dashboards, formulários, tabelas, menus, barras de navegação, modais, cartões, notificações, painéis, gráficos, listas, assistentes, telas de autenticação, configurações e qualquer outro elemento da interface.

O objetivo é transformar a aplicação em um produto moderno, profissional, intuitivo, consistente e altamente utilizável, preservando integralmente toda a lógica de negócio existente.

## Objetivos Gerais

* Criar uma interface moderna, limpa, elegante e profissional.
* Garantir consistência visual em toda a aplicação.
* Melhorar significativamente a experiência do utilizador (UX).
* Tornar a navegação simples, intuitiva e previsível.
* Reduzir a carga cognitiva do utilizador.
* Destacar apenas as informações e ações mais importantes.
* Melhorar a produtividade através de fluxos claros e eficientes.
* Garantir excelente desempenho visual em qualquer resolução.

---

# Design System

Implemente ou padronize um Design System consistente para toda a aplicação.

Padronize:

* Paleta de cores.
* Tipografia.
* Escala tipográfica.
* Espaçamentos.
* Grid.
* Margens.
* Padding.
* Bordas.
* Border Radius.
* Sombras.
* Elevação.
* Ícones.
* Estados de interação.
* Animações.
* Transições.
* Componentes reutilizáveis.
* Tokens de design.

Nenhum componente deve possuir estilos próprios quando puder utilizar componentes reutilizáveis.

---

# Simetria e Organização Visual

Toda a interface deve transmitir sensação de organização e equilíbrio.

Garanta:

* Alinhamento perfeito entre elementos.
* Espaçamentos consistentes.
* Distribuição simétrica dos componentes.
* Uso correto de grids.
* Proporções equilibradas.
* Hierarquia visual clara.
* Boa utilização dos espaços em branco.

Eliminar:

* Componentes desalinhados.
* Margens inconsistentes.
* Espaços vazios desnecessários.
* Informações excessivamente comprimidas.
* Poluição visual.

Cada tela deve parecer cuidadosamente desenhada.

---

# Layout

Revise completamente todos os layouts.

Corrija:

* Overflow horizontal.
* Quebras inadequadas.
* Scroll desnecessário.
* Sobreposição de componentes.
* Conteúdo cortado.
* Problemas de alinhamento.
* Elementos inconsistentes.
* Responsividade incompleta.

Todas as páginas devem manter o mesmo padrão visual.

---

# Navegação

Melhore toda a navegação da aplicação.

Garantir:

* Menus intuitivos.
* Fluxos simples.
* Navegação previsível.
* Breadcrumbs quando necessário.
* Menor quantidade possível de cliques.
* Localização rápida das funcionalidades.

O utilizador deve compreender naturalmente onde está e para onde pode ir.

---

# Responsividade

Toda a aplicação deve funcionar perfeitamente em:

* Monitores ultrawide.
* Desktop.
* Notebook.
* Tablet.
* Smartphone.

Garantir:

* Layout fluido.
* Componentes adaptáveis.
* Imagens responsivas.
* Tabelas responsivas.
* Menus adaptáveis.
* Modais responsivos.

Nenhum elemento pode apresentar:

* Overflow.
* Texto cortado.
* Componentes sobrepostos.
* Botões inacessíveis.
* Quebras inesperadas.

---

# Acessibilidade

A aplicação deve seguir boas práticas de acessibilidade, preferencialmente em conformidade com as recomendações WCAG 2.2 nível AA.

Garantir:

* Contraste adequado.
* Fontes legíveis.
* Espaçamento confortável.
* Área mínima de clique.
* Navegação por teclado.
* Estados de foco claramente visíveis.
* Labels corretamente associados.
* Hierarquia correta de títulos.
* Compatibilidade com leitores de ecrã.
* Não utilizar apenas cores para transmitir informação.
* Mensagens compreensíveis para todos os utilizadores.

---

# Restrições

Durante toda a implementação:

* Não remover funcionalidades.
* Não alterar regras de negócio.
* Não modificar APIs.
* Não alterar contratos existentes.
* Não modificar a estrutura dos dados, salvo quando estritamente necessário para suportar melhorias visuais.
* Preservar integralmente toda a lógica existente.
* Garantir compatibilidade com funcionalidades atuais.

---

# Critérios de Aceitação

A implementação somente deve ser considerada concluída quando:

* Todas as telas seguirem exatamente o mesmo padrão visual.
* Todos os componentes estiverem padronizados.
* Não existirem problemas de alinhamento.
* Não existirem problemas de responsividade.
* Não existirem problemas de acessibilidade.
* Não existirem inconsistências de espaçamento.
* Não existirem componentes duplicados sem necessidade.
* Não existirem problemas de overflow.
* Não existirem elementos visualmente desalinhados.
* Toda a aplicação apresentar aparência profissional e consistente.
* A navegação for intuitiva e exigir o mínimo de esforço do utilizador.
* A interface transmitir qualidade, organização, equilíbrio visual e confiança.

## Resultado Esperado

A aplicação deve apresentar um padrão visual consistente e um elevado nível de qualidade em todas as telas, proporcionando uma experiência moderna, intuitiva e acessível. O layout deve ser simétrico, responsivo e organizado, com componentes reutilizáveis, espaçamentos uniformes e navegação clara. A interface deve reduzir a carga cognitiva, destacar as ações mais importantes e permitir que qualquer utilizador localize informações e conclua tarefas com rapidez, segurança e o mínimo de esforço, sem qualquer alteração na lógica de negócio ou nas funcionalidades existentes.
