# REVISAO COMPLETA DA INTERFACE (UI/UX), LAYOUT, DESIGN SYSTEM E CORRECAO DE IMPERFEICOES VISUAIS

## REGRA DE OURO

Este prompt nao cria funcionalidades, nao altera regras de negocio, nao modifica fluxos funcionais e nao realiza transicoes de estado.

Apenas a State Machine pode alterar estados da aplicacao.

Qualquer alteracao que envolva componentes compartilhados, CSS global, Design System, contratos visuais, navegacao ou comportamento da interface durante o STATE-08 PRODUCTION_RELEASE deve ser classificada como manutencao funcional pos-release.

---

## REGRA DE COMMIT

Ao concluir qualquer alteracao:

* Criar commit local com mensagem objetiva e escopo fechado.
* O commit deve conter somente arquivos relacionados a alteracao executada.
* Nao incluir arquivos nao relacionados.
* Caso nenhuma alteracao tenha sido realizada, informar explicitamente que nao existe commit a ser criado.

---

# OBJETIVO

Executar uma auditoria completa da interface do ShiftFlow, eliminando qualquer inconsistencia visual, problema de layout, falha de responsividade, quebra de Design System, problema de UX, acessibilidade ou padronizacao.

O objetivo final e entregar uma interface com qualidade de produto comercial, moderna, consistente, limpa, profissional, altamente responsiva e visualmente refinada.

Nao considere uma tela pronta apenas porque funciona.

Considere concluida somente quando nao existirem imperfeicoes visuais perceptiveis.

---

# MODO DE INSPECAO

Nao assumir que qualquer tela esta correta.

Realizar uma auditoria completa e sistematica em absolutamente toda a aplicacao.

Para cada pagina:

1. Inspecionar de cima para baixo.
2. Inspecionar da esquerda para a direita.
3. Validar cada componente individualmente.
4. Comparar componentes equivalentes entre diferentes paginas.
5. Comparar com o Design System.
6. Corrigir qualquer inconsistencia encontrada.
7. Reexecutar a inspecao apos cada conjunto de correcoes.

Nao parar na primeira correcao encontrada.

A revisao deve ser iterativa ate que nao existam inconsistencias relevantes.

Aplicar uma identidade visual corporativa, limpa, objetiva e consistente.

Priorizar:

* Hierarquia visual clara.
* Alta legibilidade.
* Consistencia.
* Densidade adequada.
* Interfaces operacionais.
* Facilidade de leitura.
* Clareza na tomada de decisao.

* Hero Sections.
* Layout promocional.

* Fundos poluidos.
* Cards aninhados sem necessidade.
* Espacamentos irregulares.
* Fontes exageradas.

## MODO DE INSPECAO

Executar uma auditoria visual extremamente rigorosa em toda a aplicacao.

Para cada pagina, modulo e componente:

1. Percorrer toda a interface de cima para baixo.
2. Percorrer novamente da esquerda para a direita.
3. Validar individualmente cada componente visivel.
4. Comparar componentes equivalentes entre diferentes paginas.
5. Comparar o resultado com o Design System oficial.
6. Procurar diferencas visuais, mesmo que pequenas.
7. Corrigir imediatamente qualquer inconsistencia encontrada.
8. Reexecutar toda a inspecao apos cada conjunto de correcoes.

Nunca assumir que uma correcao nao afetou outras areas.

Toda alteracao deve gerar uma nova rodada de verificacao.
