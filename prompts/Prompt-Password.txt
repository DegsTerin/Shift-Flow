Faça uma análise completa do projeto e corrija o gerenciamento de credenciais e autenticação.

PROBLEMA IDENTIFICADO

Existem senhas de usuários armazenadas em arquivos .env e .env.example.

Isso é incorreto. Arquivos .env devem conter apenas configurações da aplicação e segredos de infraestrutura, nunca credenciais de usuários finais.

OBJETIVOS

1. Remover qualquer senha de usuário presente em:
   - .env
   - .env.example
   - arquivos de configuração
   - constantes hardcoded
   - scripts de inicialização
   - arquivos de seed que utilizem senhas em texto puro

2. Garantir que as credenciais dos usuários sejam armazenadas exclusivamente no banco de dados.

3. Garantir que as senhas sejam armazenadas apenas utilizando hash seguro:
   - Argon2 (preferencial)
   - bcrypt
   - ou equivalente recomendado para a linguagem utilizada

4. Garantir que nenhuma senha seja armazenada ou trafegada em texto puro além do momento do login ou cadastro.

5. Revisar todo o fluxo de autenticação:
   - cadastro de usuário
   - login
   - alteração de senha
   - recuperação de senha
   - redefinição de senha
   - criação de usuários administrativos

6. Verificar se existe:
   - senha hardcoded
   - usuário administrativo hardcoded
   - token hardcoded
   - chave secreta hardcoded
   - credenciais expostas em logs

7. Revisar os modelos, serviços, controllers, APIs, middlewares e migrations relacionados à autenticação.

8. Garantir que:
   - comparação de senha utilize função apropriada de verificação de hash
   - hashes nunca sejam retornados pela API
   - hashes nunca sejam exibidos em logs
   - hashes nunca sejam enviados para o frontend

9. Verificar possíveis vulnerabilidades:
   - armazenamento de senha em texto puro
   - exposição de credenciais
   - autenticação insegura
   - autorização inadequada
   - privilege escalation
   - SQL Injection relacionado ao login
   - brute force sem proteção
   - sessão insegura
   - JWT inseguro
   - secrets expostos

10. Atualizar documentação e comentários quando necessário.

ENTREGÁVEIS

1. Lista completa dos problemas encontrados.

2. Lista dos arquivos alterados.

3. Explicação objetiva das correções realizadas.

4. Migrations criadas ou modificadas.

5. Mudanças no banco de dados.

6. Riscos identificados e respectivas correções.

7. Confirmação de que:
   - nenhuma senha de usuário permanece em .env
   - nenhuma senha de usuário permanece hardcoded
   - todas as senhas são armazenadas apenas no banco de dados utilizando hash seguro

Antes de implementar qualquer alteração estrutural significativa, explique o problema encontrado e apresente o plano de correção.
