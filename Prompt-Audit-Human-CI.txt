Objetivo: Realizar uma auditoria técnica completa, profunda e extremamente rigorosa em todo o projeto.

Escopo obrigatório:

1. Analisar 100% do código-fonte de todos os arquivos do projeto.
2. Analisar todos os arquivos de configuração.
3. Analisar todos os arquivos .txt, .md, .json, .yaml, .yml, .env.example, documentação e demais artefatos existentes.
4. Mapear integralmente a arquitetura do sistema.
5. Validar fluxos de negócio, regras de negócio, integrações e dependências.
6. Identificar falhas funcionais, técnicas, arquiteturais e operacionais.

Executar uma Human CI (Human Code Inspection) completa e detalhada em todo o projeto.

A auditoria deve verificar:

• Bugs conhecidos e potenciais.
• Erros de lógica.
• Fluxos quebrados.
• Fluxos incompletos.
• Casos de borda não tratados.
• Tratamento inadequado de exceções.
• Condições de corrida (Race Conditions).
• Problemas de concorrência.
• Loops infinitos.
• Vazamentos de memória.
• Código morto.
• Código duplicado.
• Código desnecessário.
• Dependências não utilizadas.
• Dependências obsoletas.
• Problemas de performance.
• Gargalos.
• Vulnerabilidades de segurança.
• Exposição de dados sensíveis.
• Falhas de autenticação.
• Falhas de autorização.
• Falhas de validação de entrada.
• Injeções.
• Problemas de escalabilidade.
• Problemas de manutenibilidade.
• Problemas de observabilidade.
• Problemas de monitoramento.
• Problemas de logs.
• Problemas de UX.
• Problemas de acessibilidade.
• Problemas de compatibilidade.
• Problemas de consistência de dados.
• Possíveis cenários de falha em produção.

Para cada problema encontrado:

1. Informar o arquivo exato.

2. Informar a linha exata ou bloco exato.

3. Explicar detalhadamente o problema.

4. Explicar o impacto real.

5. Classificar a severidade:

   * Crítica
   * Alta
   * Média
   * Baixa

6. Explicar o risco técnico.

7. Explicar o risco de negócio.

8. Apresentar a correção recomendada.

9. Apresentar a correção ideal.

10. Exibir exemplos de código quando aplicável.

Realizar inspeção linha por linha, função por função, classe por classe, componente por componente, serviço por serviço, API por API, fluxo por fluxo e arquivo por arquivo.

Não assumir que algo está correto apenas porque compila ou possui testes.

Questionar todas as premissas do sistema.

Validar se a implementação corresponde ao comportamento esperado.

Buscar ativamente falhas ocultas, inconsistências, riscos futuros, dívidas técnicas e comportamentos inesperados.

Ao final gerar:

1. Relatório Executivo.
2. Relatório Técnico Completo.
3. Ranking dos problemas mais críticos.
4. Matriz de Risco.
5. Lista de Correções Prioritárias.
6. Plano de Refatoração.
7. Plano de Hardening de Segurança.
8. Plano de Otimização de Performance.
9. Estimativa de esforço para correção.
10. Checklist final de produção.

Nível de criticidade da auditoria: EXTREMO.

Profundidade de análise: MÁXIMA.

Nenhum arquivo deve ser ignorado.
Nenhuma linha deve ser presumida correta sem validação.
Nenhuma conclusão deve ser feita sem evidência técnica.
