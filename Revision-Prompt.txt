OBJETIVO

Status da revisao:
Documento consolidado em 2026-06-22 como entrada operacional pos-release.
Este arquivo nao altera estado, nao substitui a State Machine e deve ser executado somente por fase permitida, com diagnostico previo, evidencias, gates e atualizacao dos documentos canonicos.

Realizar uma revisão completa do sistema ShiftFlow para corrigir problemas funcionais, de usabilidade, responsividade e fluxo operacional.

O sistema deve funcionar corretamente em:

* Desktop
* Mobile
* Tablet
* Light Mode
* Dark Mode
* PT-BR
* EN-GB

O objetivo principal do sistema é servir como plataforma de reporte operacional de turnos, permitindo que equipes, coordenadores, gestores e outros turnos visualizem em tempo real o status das atividades operacionais.

O sistema também deve ser adequado para exibição contínua em TVs e painéis de monitoramento.

---

ANÁLISE GERAL OBRIGATÓRIA

Antes de implementar qualquer correção:

1. Auditar todo o frontend.
2. Auditar todo o backend.
3. Auditar integrações frontend/backend.
4. Auditar estados globais.
5. Auditar componentes reutilizáveis.
6. Auditar rotas.
7. Auditar formulários.
8. Auditar filtros.
9. Auditar sistema de pesquisa.
10. Auditar responsividade.

Gerar relatório dos problemas encontrados antes das correções.

---

CORREÇÃO 01 - RESPONSIVIDADE

Problema:

O sistema não está totalmente responsivo.

Objetivo:

Garantir funcionamento correto em:

* Mobile
* Tablet
* Desktop
* TVs corporativas

Validar:

* Menus
* Dashboards
* Kanban
* Tabelas
* Formulários
* Modais
* Cards
* Gráficos

Critérios:

* Nenhum elemento pode ultrapassar a largura da tela.
* Nenhum scroll horizontal indevido.
* Componentes devem reorganizar automaticamente conforme resolução.

---

CORREÇÃO 02 - MENU LATERAL

Problema:

Itens possuem tamanhos inconsistentes.

Objetivo:

Padronizar completamente o menu lateral.

Requisitos:

* Altura idêntica para todos os itens.
* Espaçamento uniforme.
* Alinhamento consistente.
* Ícones padronizados.
* Melhor aproveitamento vertical.
* Comportamento consistente entre desktop e mobile.

---

CORREÇÃO 03 - FILTROS

Problema:

Filtros não estão funcionando.

Objetivo:

Implementar filtros reais conectados aos dados.

Aplicar em:

* Dashboard Principal
* Dashboard por Equipe
* Kanban
* Gestão de Equipes
* Gestão de Turnos
* Gestão de Usuários
* Relatórios

Permitir filtragem por:

* Cliente
* Equipe
* Turno
* Analista
* Prioridade
* Status
* Data inicial
* Data final

Critérios:

* Filtros devem funcionar simultaneamente.
* Persistência de filtros durante navegação.
* Atualização automática dos dados exibidos.

---

CORREÇÃO 04 - REGISTRO COMPLETO DE ATIVIDADES

Toda atividade deve possuir:

Identificação:

* ID
* Empresa
* Cliente
* Equipe
* Turno

Informações:

* Título
* Detalhe da atividade

Campos obrigatórios:

* O que foi solicitado
* O que foi feito
* O que está em andamento
* O que está pendente
* Como foi finalizado
* Observações

Metadados automáticos:

* Data de criação
* Usuário criador
* Data da última atualização
* Usuário responsável pela atualização

Esses campos devem ser preenchidos automaticamente pelo sistema quando aplicável.

---

CORREÇÃO 05 - HISTÓRICO COMPLETO

Implementar trilha de auditoria.

Registrar:

* Criação
* Edição
* Atualização
* Mudança de status
* Exclusão lógica

Cada evento deve armazenar:

* Data
* Hora
* Usuário
* Ação executada
* Valor anterior
* Valor novo

O histórico deve ser imutável.

---

CORREÇÃO 06 - BOTÃO "+ NOVO"

Problema:

Não funciona em nenhuma tela.

Objetivo:

Corrigir todas as ações de criação.

Validar:

* Rotas
* Formulários
* Modais
* APIs
* Persistência no banco

Critério:

Todo botão "+ Novo" deve abrir corretamente o fluxo de criação correspondente.

---

CORREÇÃO 07 - VISUALIZAÇÃO DE REGISTRO

Ao clicar em qualquer registro:

Abrir modal, drawer ou painel lateral contendo:

* Dados completos
* Histórico
* Comentários
* Anexos
* Informações do responsável
* Datas importantes

Sem redirecionar para outra página.

---

CORREÇÃO 08 - EDIÇÃO DE REGISTROS

Ao abrir um registro:

Disponibilizar:

* Editar
* Atualizar
* Salvar
* Excluir (soft delete)

Toda alteração deve atualizar automaticamente o histórico.

---

Objetivo:

Implementar busca funcional.

Pesquisar por:

* ID

* Cliente
* Equipe
* Usuário
* Status

Aplicar em todas as telas relevantes.

Características:

* Atualização automática
* Auto refresh
* Layout otimizado para tela grande
* Indicadores visuais de SLA

REGRAS DE IMPLEMENTAÇÃO

Não alterar arquitetura principal sem necessidade.
